Static vs dynamic QR codes

One type works forever and costs nothing; the other can be changed but depends on a service staying alive. Here is when each makes sense.

Looking for a QR code generator, you will run into two terms — static and dynamic codes. The difference between them is fundamental and decides whether your code still works in five years.

Static QR codes

A static code holds the data inside its own pattern. If it contains a link to your site, that link is literally encoded in those black squares. The phone reads it and opens it directly — nothing is downloaded, nothing is redirected.

Advantages:

  • It works permanently. It cannot expire, because it depends on no service.
  • Nobody tracks who scanned it or when.
  • It is free and needs no account.
  • It keeps working even if the company that created it disappears.

Drawbacks:

  • The content cannot be changed afterwards. A different link means creating and printing a new code.
  • Large amounts of data make the pattern denser, so the code must be printed bigger.
  • You will not know how many times it was scanned.

Dynamic QR codes

A dynamic code does not contain your link. It contains a short address pointing at the provider's server, which then redirects visitors wherever you currently tell it to. You change the destination in a dashboard and the code itself stays the same.

Advantages:

  • The destination can be changed after the code has been printed.
  • Providers usually offer scan statistics.
  • The pattern is always sparse and easy to read, since it only holds a short address.

Drawbacks — and these deserve to be taken seriously:

  • The code works only while you keep paying. When the subscription ends, the redirect dies and printed codes become worthless.
  • It depends on the company surviving. If the provider shuts down, so do your codes — however many you have printed.
  • Scans are tracked and the resulting data is processed by a third party.
  • Visitors see an unfamiliar domain when the code opens, not yours.

Watch out for "free" generators

This is a common trap. Some sites offer a free code but produce a dynamic one with a free trial period. You print hundreds of copies, and after seven or fourteen days the code stops working and asks for payment.

How to spot it before it is too late:

  • Scan the finished code and look at the address the phone shows. An unfamiliar domain means a dynamic code.
  • If the generator requires an account, the codes are usually tied to it.
  • Look in the terms for words like "trial", "expires" or "scan limit".

Which type to choose

A static code is the better choice when:

  • The code carries data that will not change — Wi-Fi access, contact details on a card, plain text.
  • You are printing something long-lived — business cards, signs, product labels.
  • You do not want to depend on an outside service or pay a monthly fee.
  • Scan statistics do not matter to you.

A dynamic code makes sense when:

  • The destination genuinely will change — a seasonal campaign or a frequently updated menu.
  • You need to measure how many people scanned the code.
  • It is a short campaign where paying for its duration is acceptable.
  • You accept paying for the service indefinitely.

A practical middle ground

If you need a changeable destination but do not want to depend on someone else's service, there is a middle path: create a static code pointing at an address on your own domain, for example yourdomain.com/menu. You can then redirect that address wherever you like, whenever you like.

You get the flexibility of a dynamic code while keeping control — as long as your domain works, so does the code.
